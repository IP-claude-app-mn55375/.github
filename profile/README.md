<p>三四个人共用一个后台，是很多小团队起步时的常态。这种做法本身没错，问题出在选择线路时没有一套可对照的条件，最后变成谁便宜买谁，用起来才发现撞线、抢号、交接混乱。这篇把选型拆成一份决策清单：先认领前提，再按池子、分摊、移动端三组逐项打勾，最后给出三条可以直接否决的底线。价格为经验区间，仅供参考。</p>
<h2>一、决策前先认领四个前提</h2>
<p>清单不是所有人都适用，所以要先确认几件事。前提不成立，后面的打分就没有意义，先去解决前提。</p>
<h3>前提一：人数与在线时段是否重叠</h3>
<p>三个人分布在三个时区，等于全天都有人在线，实际占用接近独占；三个人都在同一时区同一时段工作，占用的其实是三条并发。这两种情况对池子的要求完全不同，前者需要覆盖更多城市，后者只需要足够并发。</p>
<h3>前提二：是否真的共用后台</h3>
<p>「合用一个后台」有两种：一种是各自登录自己的号，只是共享同一套管理界面；另一种是多个人登录同一个号。前者可以接受，后者要极力避免，同一账号在不同设备、不同地址频繁切换，是最容易触发验证的模式。</p>

<h2>二、清单第一组：池子规模与重复率</h2>
<p>「不常撞线路」这句承诺要能量化，否则无法验收。两个指标：池子规模、重复率。买之前让服务商给出这两个数，买之后自己抽测复核。</p>
<h3>重复率怎么算</h3>
<p>取同一周内每个账号使用过的出口地址，统计出现两次以上的地址数量，除以总地址数。低于 5% 算优秀，5% 到 15% 可接受，高于 15% 说明池子复用太严重。抽测时至少取五个号、连续三天，样本太小没有意义。</p>
<h3>池子多大算够</h3>
<p>经验公式：池子规模至少是账号数的五倍，且同城地址不少于账号数的两倍。理由是家庭宽带的地址会变动，池子太紧时变动后容易分到别人用过的地址，重复率立刻上升。</p>

<h2>三、清单第二组：分摊与权限</h2>
<p>团队分摊最怕的不是算钱，是权限。谁能看账单、谁能改线路、谁能加号，这三件事不写清楚，后面一定扯皮。</p>
<h3>按人分摊还是按号分摊</h3>
<p>按人简单，人头数乘以单价，适合人数稳定的小团队。按号更公平，适合号量波动大的场景。两种都可以，但不能混用——一半按人一半按号，账永远对不平。折中做法是按号分摊、按人预收，月底多退少补。</p>

<h2>四、清单第三组：移动端特有项</h2>
<p>App 和网页端的差别比想象中大。移动网络的出口切换更频繁，App 的长连接更敏感，验证方式也常常不同，这一组不能照抄网页端的配置。</p>
<h3>App 与网页端的三个差别</h3>
<p>第一，粘性要求更高：移动端切网会中断长连接，粘性短会导致一次使用中途换地址。第二，定位权限要慎开，开了就要与出口城市一致。第三，推送通道可能绕开代理，需要单独确认。</p>

<h2>五、签字前的最后三条</h2>
<p>前面打勾再多，这三条不满足就换一家。它们不是加分项，是否决项。</p>
<h3>三条否决项</h3>
<p>一，无法提供逐条 ASN 与城市查询结果；二，换线必须整批换、不能单条替换；三，计费口径写不清按什么单位结算。三条里任何一条成立，说明对方要么能力不足，要么不愿意承担后续责任，都不适合长期合作。</p>
<h2>常见问答</h2>
<h3>三四个人的团队，需要买独享线路吗？</h3>
<p>答：核心号需要，辅助号可以共享。判断标准是停摆损失：某个号停了会直接影响收入，就单独给它一条独享；只用于查资料、看趋势的号，共享池完全够用。</p>
<h3>池子规模按人数还是按号数算？</h3>
<p>答：按号数。人数只影响并发，池子覆盖的是地址多样性。号数增长时池子要同步扩，否则重复率会随着号量上升而变高。</p>
<h3>共用一个后台，怎么避免互相挤下线？</h3>
<p>答：各登各号是前提。同一个号不要多人同时登录，如果确实需要协作，约定「一人主用、其他人只读」，并且只读的人不要在同一时间反复刷新。</p>
<h3>App 端频繁要求重新登录，是线路问题吗？</h3>
<p>答：先看粘性。粘性短导致 IP 中途变更，App 会视为环境变化而要求重登。把粘性拉长到三十分钟以上再观察一周，多数情况会明显改善。</p>
